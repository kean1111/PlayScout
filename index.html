✓ Parsing Standards
Specs are matched by test() blocks — add an ID tag like @id-INSTALLERS-001, a title prefix like [TR-001] [Priority: High] [Status: Passed], or a test.info().annotations.push(...) call, and wrap steps in test.step() (falls back to // comments if none exist). JSON accepts hand-written manifests (tests/cases array), Playwright's own --reporter=json output, and Mocha's JSON reporter — all auto-detected. .xml files are read as JUnit reports (pass/fail/skip pulled from <failure>/<error>/<skipped>). .jsonl (or a --reporter=blob .zip, extracted automatically) is read as Playwright's blob event log — the same @id/priority/requirement annotations carry through. Plain .txt files use a title line followed by numbered steps. Anything else — CSV, HTML exports, messy logs — use Smart Import (AI) instead of a fixed convention.
